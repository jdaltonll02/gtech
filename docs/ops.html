Ops & Infrastructure Guide

Gibson Technologies — GCP VM + Docker Compose + Neon PostgreSQL

Stack Overview

The platform runs as a set of Docker Compose services on a GCP VM. PostgreSQL is fully managed by Neon (serverless). All public traffic enters through host Nginx on ports 80/443.

Browser
  │
  ▼
Nginx (host, port 80/443)
  │
  ▼
Frontend container (127.0.0.1:3000)
  ├── /api/*  → API container (172.x.x.x:8000)
  │              ├── Neon PostgreSQL (external, TLS)
  │              ├── Redis container (internal)
  │              └── Celery Worker / Beat
  └── /*      → React SPA (static files)

After editing .env, restart affected services:

cd /home/Jdalton/gtechwebsite
docker compose restart api worker beat

Start / Stop

Start all services

cd /home/Jdalton/gtechwebsite
docker compose up -d

Stop all services

docker compose down

Restart a single service

docker compose restart api      # restart API only
docker compose restart worker   # restart Celery worker
Auto-restart: All containers use restart: unless-stopped. They will automatically come back up after a VM reboot.

Updating the Application

cd /home/Jdalton/gtechwebsite

# Pull latest code
git pull origin main

# Rebuild and restart changed services
docker compose build
docker compose up -d --no-deps --build api worker beat frontend

# Confirm migrations ran
docker compose logs api | grep -i alembic
Alembic migrations run automatically on API container start — no manual step needed.

Database Migrations

# Check current revision
docker compose exec api alembic current

# Apply all pending migrations
docker compose exec api alembic upgrade head

# Roll back one step
docker compose exec api alembic downgrade -1

# Create a new migration (after model changes)
docker compose exec api alembic revision --autogenerate -m "description"

Backups

Database (Neon)

Neon provides automatic point-in-time restore (7 days free tier, 30 days on paid plans). For additional manual backups, a cron job runs daily at 3:00 AM:

# Manual on-demand backup
docker run --rm postgres:18-alpine \
  pg_dump "postgresql://neondb_owner:PASSWORD@HOST/neondb?sslmode=require" \
  > /home/Jdalton/backups/db_$(date +%Y%m%d).sql

# Restore
docker run --rm -i postgres:18-alpine \
  psql "postgresql://neondb_owner:PASSWORD@HOST/neondb?sslmode=require" \
  < /home/Jdalton/backups/db_20260101.sql

Media files

Media uploads live in the Docker volume gtechwebsite_media_data. A cron job backs them up daily at 3:30 AM to /home/Jdalton/backups/. Both DB and media backups are retained for 7 days.

# List backups
ls -lh /home/Jdalton/backups/

# View cron schedule
crontab -l

SSL / Certificates

Certificates are managed by Certbot (snap) and stored at /etc/letsencrypt/live/gibtechs.com/. Auto-renewal is handled by a systemd timer.

# Check timer status
sudo systemctl status certbot.timer

# Test auto-renewal (dry run)
sudo certbot renew --dry-run

# Force renewal
sudo certbot renew --force-renewal
sudo systemctl reload nginx
Certificate expires 2026-09-02. Auto-renew will fire ~30 days before expiry. If it fails, run the force-renewal command above.

Celery Flower Dashboard

Flower runs on 127.0.0.1:5555 and is not publicly accessible. Access it via SSH tunnel:

ssh -L 5555:127.0.0.1:5555 Jdalton@104.196.57.152

Then open http://localhost:5555 in your browser. Login with FLOWER_USER / FLOWER_PASSWORD from backend/.env.

Containers Not Starting

docker compose ps

502 Bad Gateway

The API container may still be starting — health check takes up to 40 s on boot.

docker compose logs -f api
# Wait for: INFO: Application startup complete.

Database / Neon Errors

  • Confirm DATABASE_URL ends with ?sslmode=require
  • Use the pooled connection string from Neon Dashboard
  • Check if the Neon project is suspended — log in to console.neon.tech and wake the branch
docker compose exec api alembic current
docker compose exec api alembic upgrade head

Out of Disk Space

df -h
docker system prune -f        # removes stopped containers & dangling images
docker volume ls              # NEVER prune media_data or redis data volumes

SSL Certificate Not Renewing

sudo certbot renew --force-renewal
sudo systemctl reload nginx

Security Checklist

  • SECRET_KEY is a random 64-character hex string
  • FIRST_SUPERADMIN_PASSWORD changed after first login
  • STRIPE_WEBHOOK_SECRET is the live Stripe signing secret
  • FLOWER_USER and FLOWER_PASSWORD are non-default values
  • Flower accessed via SSH tunnel only — not open in GCP firewall
  • Redis port 6379 is NOT exposed in GCP firewall
  • ALLOWED_ORIGINS contains only https://gibtechs.com
  • SMTP credentials are app-specific passwords
  • HTTPS redirect working: curl -I http://gibtechs.com returns 301
